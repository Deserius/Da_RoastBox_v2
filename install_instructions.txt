This is a practical, owner-operated guide for running the application OUTSIDE
Arena.ai. You do not need an Arena browser tab or an Arena preview server
running after you have downloaded the complete project.

There are TWO different deployment methods:

  A. LOCAL: the application runs on your own computer. A browser connects to
     http://127.0.0.1:3000. Your computer must remain on while you use it.

  B. CLOUD: Render runs the application at your assigned HTTPS website URL.
     Your computer does not need to remain on. The Free service can sleep,
     restart, hit quotas, or lose unfinished work. It is a PRIVATE BETA, not
     an always-on production guarantee.

The app's Python backend, MongoDB database, React frontend and FFmpeg remain
intact. This guide does not replace them with Supabase/Postgres, create a
second website, or require a paid Render disk.

IMPORTANT LIMITS BEFORE YOU BEGIN:

  1. A software download does NOT include private API keys, database records,
     old purchases, generated shows, or customer media. Keep those private.
     A source ZIP is not a database/media backup.

  2. Free web hosting does NOT make OpenRouter, OpenAI, ElevenLabs, email,
     storage transfers or other provider usage free. Configure provider
     spending controls before permitting generation or voice samples.

  3. Keep Stripe in TEST mode. Do not switch to live keys or real sales while
     following this guide. No checkout or paid AI generation is necessary
     just to install, deploy, or check the health endpoints.

  4. Preserve your EXISTING JWT_SECRET if bringing existing data. That secret
     is also used to derive encryption for saved user-supplied API keys.
     Changing it can make those saved keys unreadable.

  5. NEVER delete .data\mongo, reset user balances, regenerate old shows, or
     overwrite a richer existing installation as an installation repair.
     Do not stop MongoDB to fix a web-server/package problem.

  6. The Google button still uses the managed Emergent authentication service
     implemented in the source. It does not yet provide a separately wired,
     self-managed Google OAuth client. Your NEW local/cloud origin must be
     accepted by that managed provider. Merely setting GOOGLE_CLIENT_ID or
     GOOGLE_CLIENT_SECRET will not replace this integration. See Section 08.

  7. The current Free Render recipe uses a PRIVATE Vercel Blob store. Vercel
     Hobby is restricted to personal/non-commercial use. TEST payments do
     not automatically make a commercial/branded app eligible. Confirm your
     eligibility before relying on that plan. If it is not eligible and no
     approved compatible private store exists, STOP the cloud deployment;
     do not make media public or silently start a paid plan. Local use can
     continue. See Section 16.

  8. This is the recovered/current downloadable source, not a certification
     that it exactly equals every richer historical native release. Compare
     before updating an older customized installation.

  9. The prepared Windows files were assembled and checked in a Linux build
     workspace. Native Windows double-click, certificate trust, UAC, default
     browser and physical-phone behavior still need verification on your
     actual hardware. A completed deployment also needs actual-origin
     provider/authentication acceptance; a filled variable is not proof.

This file contains NO real credentials. All placeholder names must be

No instructions in this file authorize an assistant to create accounts,

02. UNDERSTAND ADDRESSES, PORTS AND FOLDERS
==========================================================================

LOCAL WINDOWS ARCHITECTURE:

  Your browser
      -> http://127.0.0.1:3000
      -> Node serves the compiled frontend and proxies /api
      -> FastAPI at http://127.0.0.1:8001
      -> MongoDB at 127.0.0.1:27017
      -> local media plus configured internet providers

The web address to OPEN is port 3000. Port 8001 is the API, not the full UI.
Port 27017 is the database protocol. It is NOT a website and will not display
the application in your browser. Arena's existing preview port 3211 is not the
default for your downloaded local installation.

127.0.0.1 and localhost mean THE COMPUTER USING THAT ADDRESS. If you send a
friend a localhost URL, it points to your friend's own computer, not yours.
Use the Render HTTPS URL for normal remote access.

RENDER ARCHITECTURE:

  Browser -> https://YOUR-ASSIGNED-SERVICE.onrender.com
          -> ONE Docker web service: FastAPI serves frontend AND /api
          -> external TLS MongoDB
          -> approved PRIVATE durable Blob storage
          -> configured real writer, speech, auth, mail and Stripe TEST

The Render container uses its platform PORT, normally through the Docker
fallback 10000. You do NOT expose local ports 3000/8001/27017 on Render and
must not put localhost:8001 into the browser build.

IMPORTANT LOCAL FOLDERS:

  Project root           Folder containing thelaunch.bat and install.py.
  backend\.env           Private backend settings and secrets.
  frontend\.env          PUBLIC frontend/build settings; never secret keys.
  runtime\windows-x64\   Shipped Windows programs and local runtime payload.
  .venv\                 Separate Python environment when source/repair needs it.
  .cache\                Installer temp/cache and preserved runtime repairs.
  .data\mongo\           Local MongoDB database files. Never delete as a fix.
  backend\local_storage\ Local stored customer media by default in local mode.
  backend\audio_cache\   Audio/cache originals; preserve during backups/moves.
  backend\media_tmp\     Temporary media work, not a durable cloud media store.
  frontend\build\        Compiled site; normal launcher reuses a matching build.
  .private\              Private owner reports/exports/config, never Git content.

Your configured LOCAL_STORAGE_DIR or remote store can override the default
media location. The ACTUAL configured location is authoritative.

03. DECIDE: NEW EMPTY INSTALLATION OR PRESERVE EXISTING DATA
==========================================================================

Before starting, choose the correct case. This is especially important if
you already used an older native version or have balances/purchases/history.

CASE A - genuinely new empty local install:

  - Extract to a NEW folder.
  - Let the launcher create missing env files and a new persistent secret.
  - The fresh preview configuration normally selects da_roastbox_preview,
    local media and explicit preview login.
  - No previous accounts/shows are imported from the ZIP.

CASE B - existing users/history/media must continue:

  - Identify the actual authoritative installation, database and media store.
    Do not assume a recovered ZIP or an older backup is the newest copy.
  - Back up configuration, database and original media separately.
  - Keep the exact existing JWT_SECRET and the actual DB_NAME.
  - Do not rename the database or generate a replacement encryption secret.
  - Do not overwrite a running MongoDB data directory with a copied folder.
  - Compare code before updating a customized/richer native app.
  - Do not run old/new app recovery workers against the same unfinished jobs
    without a controlled cutover. Back up before pointing new code at old data.
  - When moving hosts, follow Section 17. A source extraction alone is NOT
    a migration. An empty database is not a reason to recreate purchases,
    regenerate historical shows or manually add credits.

If a newly extracted app looks empty, first check whether its backend .env
points at the intended database and media store. A different DB_NAME can
make an existing database look missing even though the original still exists.

Normal NEW accounts receive 25 credits. Existing account balances and
entitlements are authoritative. Explore's explicit preview behavior is not
permission to reset or recharge normal users.

07. DAY-TO-DAY LOCAL STARTUP, SHUTDOWN, SHORTCUTS AND REPAIRS
==========================================================================

NORMAL START:

  Double-click thelaunch.bat in the same extracted project folder.
  It reuses intact runtimes/builds and opens the default browser after
  readiness. An already-running matching app is reused, not duplicated.

NORMAL STOP:

  Press Ctrl+C in THAT app's launcher console. Its own API/frontend processes
  stop. MongoDB is deliberately left running. Do not use a broad taskkill
  command, kill every Python/Node process, or stop mongod to fix the UI.

DESKTOP SHORTCUT:

  Right-click the actual thelaunch.bat -> Show more options / Send to ->
  Desktop (create shortcut), or use Windows' Create shortcut action.
  Keep the shortcut target pointing to the BAT INSIDE the app folder.
  Its Start in location should be the project root. Do not copy just the BAT
  onto the Desktop or out of the extracted tree.

OPTIONAL COMMANDS (PowerShell, opened IN the project root):

  .\start.bat --no-browser
      Start without automatically opening the browser.

  .\start.bat --skip-mongodb
      Use only your reachable configured database. This does not download
      or start a portable database and does not fix an unreachable URI.

  .\start.bat --port 3050
      Explicitly choose frontend port 3050 if you have an intentional clash.
      The API still uses its configured/default port. Do not randomly cycle
      ports to avoid understanding which existing service owns them.

  .\start.bat --api-port 8011
      Explicitly choose a different API port. The local proxy follows it.
      Frontend/API ports must be different; never use 27017 for the website.

  .\start.bat --repair
      STOP THE APP'S WEB WINDOW FIRST; LEAVE MONGODB RUNNING.
      Reinstall packages in a separate venv and force a frontend rebuild.
      This can need internet, time, RAM and 4 GiB+ working space. It is not
      the normal first step for a database/key problem or disk-full retry.

  python start.py
  python Launcher.py
      Equivalent setup/start paths IF a supported Python can already run.
      A .py file cannot execute itself when Python is missing. Prefer BAT
      for no-prerequisite double-click use.

  Advanced override names, only when deliberately needed:
    ROASTBOX_PYTHON_EXE, ROASTBOX_NODE_EXE, ROASTBOX_MONGOD_EXE.

DATA / LOCAL NETWORK CAUTION:

10. LOCAL TROUBLESHOOTING BY SYMPTOM
==========================================================================

"The browser does not load on 27017"
  That port is MongoDB. Open http://127.0.0.1:3000 instead. Do not move/stop
  the database to make 27017 a web page.

"The launch file says project files are missing"
  Extract the entire ZIP and launch from the folder containing install.py.
  Do not run inside the ZIP viewer or copy only the BAT out of the folder.
  Check for an extra inner project folder after extraction.

"Nothing happens when I double-click start.py"
  A Python file needs a working interpreter/association. Use thelaunch.bat.
  Do not install unrelated Store launchers or copy Linux Python files.

"Python is missing or Microsoft Store opens"
  The BAT bootstrap avoids the Store placeholder, searches supported x64
  Python 3.11-3.13 and normally uses the bundled interpreter. If that runtime
  is missing/corrupt, it can fetch the pinned official installer with SHA256
  and publisher checks. Extract a complete trusted ZIP first.

"Python publisher/signature/hash verification failed"
  Do not bypass verification. Check archive checksum, complete extraction,
  Windows date/certificate updates, security policy and your trusted network.
  Ask an administrator if a managed system blocks the trusted program.

"Missing packages / No module named fastapi / No module named pip"
  You may have launched the wrong global Python or not unpacked the payload.
  Use the BAT, not a random global pip command. For genuine damage, stop only
  the web app and use --repair. Do not pip-install into the sealed runtime
  by hand or delete data to fix package imports.

"[WinError 112], [Errno 28], disk full or quota exceeded"
  Check BOTH project drive and Windows/system drive, plus any quota. Example:

    Get-PSDrive -PSProvider FileSystem

  Free space deliberately; rerun normal launch. Do not automatically purge
  all caches, delete .data\mongo/media, or repeatedly --repair a full disk.

"Frontend/API port already occupied"
  Inspect before changing anything. Read-only PowerShell command:

    Get-NetTCPConnection -State Listen | Where-Object { $_.LocalPort -in @(3000,8001,27017) } | Select-Object LocalAddress,LocalPort,OwningProcess

  Identify the owning PID in Task Manager. Reuse the correct app or close
  only your own conflicting web window. Do not kill all Node/Python/Mongo
  processes. Use explicit port overrides only if intentionally needed.

"MongoDB cannot start / DLL / AVX / unsupported CPU error"
  Check Windows x64/CPU support and complete extraction of the app-local C++
  files. Read the visible startup message and .data\mongo-27017.log. A source
  fallback can need Microsoft's legitimate runtime installer. Do not delete
  the database or try to force an incompatible CPU/OS to run it.

"The app is empty; my old account/history is missing"
  A new ZIP is not a backup. Verify the ACTUAL MONGO_URL, DB_NAME, original
  JWT_SECRET and media store. Follow Section 17 for an approved transfer.
  Do not create compensating credits, checkouts, fake history or new audio.

"The home page opens but generation or speech fails"
  Check actual private provider keys, model permissions, budget/credits,
  provider status and the correct environment file. Explore app credits do
  not pay external providers. A 429/provider refusal is not fixed by changing
  models silently or removing Clean/off-limits/entitlement/21+ checks.

"Google returns to Arena/old deployment, or login is rejected"
  Use the current source/build, correct chosen origin and callback routes.
  Verify managed provider origin acceptance. Existing browser sessions are
  origin-specific; reauthenticate. Clearing only this browser site's cache/
  session can log you out but does not repair/migrate a database. Never
  delete server data or disable OAuth state checks as a login fix.

"No email arrives"
  Inspect actual email capability, sender/domain verification, correct
  APP_BASE_URL, mail provider logs and spam filtering. Do not assume test
  senders deliver to arbitrary users. Render Free requires HTTPS delivery,
  not SMTP on its blocked ports. Never fake success or skip verification.

"No intro sound / download blocked"
  Focus the standalone browser page and use a real tap/Enter/Space. Check site
  sound permissions and device mute. For MP4 downloads allow the legitimate
  browser download and use a full browser tab, not a restricted embedded view.

"A generation/reel is slow or the browser disconnected"
  Do not immediately resubmit. Check Recent shows/reel status and account
  state first; the provider may already have billed or work may have finished.
  Use existing progress/recovery controls instead of creating duplicate jobs.

17. PRESERVE / MOVE EXISTING DATABASE AND MEDIA SAFELY
==========================================================================

THIS SECTION IS OPTIONAL ONLY WHEN AN ACTUAL OWNER-APPROVED MOVE IS NEEDED.
It performs real private-data operations when --apply is used. It was not
executed merely to write this guide. Do not run it against an old/richer app
or destination you have not explicitly selected.

If you are deliberately starting a new empty cloud project with no prior
records/media to preserve, document that decision and skip transfer commands.
If reusing the same authoritative remote DB/store, avoid unnecessary copying
and plan only worker cutover and verification.

17.A BACKUP / CONSISTENCY PREPARATION

  1. Identify the actual authoritative DB_NAME, MONGO_URL, JWT_SECRET and all
     media/cache roots or remote object stores. The source ZIP has none of
     those customer records. Missing recovered history is not permission
     to regenerate a show, re-buy a purchase or credit someone again.

  2. Retain independent encrypted backups of private env/key material,
     database and original media. Protect Windows backups with appropriate
     owner ACLs/encryption; POSIX mode 600 is not a Windows ACL guarantee.

  3. Pause APPLICATION WRITES under your control, including other deployed
     app workers using that source database. Finish/account for in-flight
     generation/reel/payment work. Stop only web app windows/workers as
     appropriate. LEAVE MONGODB RUNNING. A consistent standalone export needs
     writes actually paused, not copying live WiredTiger files or stopping DB.

  4. Keep target application writes stopped through restore/reconciliation.
     Keep Render DATA_IMPORT_CONFIRMED=false so startup does not race a copy.

  5. For database export/restore, install the official MongoDB Database Tools
     on your owner-controlled computer (reference M2). mongodump/mongorestore
     are NOT bundled just because mongod.exe is bundled. Add their bin folder
     to your selected terminal PATH through a trusted deliberate setup.
     Do not put passwords/URIs directly into a public command line.

  6. Run helper commands with the prepared project Python. Define $Py as in
     Section 13. The commands below are PowerShell ONE-LINE examples. Replace
     example source paths with YOUR actual authoritative locations.

  Example variables (REPLACE THESE; do not guess your authoritative folder):

    $SourceEnv = "C:\YourAuthoritativeApp\backend\.env"
    $SourceMedia = "C:\YourAuthoritativeApp\backend\local_storage"
    $SourceAudio = "C:\YourAuthoritativeApp\backend\audio_cache"
    $TargetEnv = ".private\render.env"

  $SourceMedia must be the actual media root containing da-roastbox/ when
  using the local storage namespace. Remote-only sources require their own
  owner-approved export/inventory; this helper does not fetch every old vendor.

17.B READ-ONLY SOURCE INVENTORY

  From the current helper project, with writes still paused:

    & $Py scripts\data_inventory.py snapshot --env-file "$SourceEnv" --output .private\source-before.json --media-root "$SourceMedia" --audio-cache "$SourceAudio"

  The helper reads canonical Mongo records and hashes local media; it does
  not modify Mongo. It creates an exclusive PRIVATE manifest and refuses
  overwriting it. Use a new filename for a later inventory, not --force.

17.C REVIEW THE DATABASE TRANSFER PLAN FIRST

  These commands, WITHOUT --apply, are plans and make no database writes:

    & $Py scripts\mongo_transfer.py export --env-file "$SourceEnv" --archive .private\authoritative.archive.gz
    & $Py scripts\mongo_transfer.py restore --env-file "$TargetEnv" --archive .private\authoritative.archive.gz

  Do not infer that a printed plan means a backup or restore actually occurred.
  The private target env needs the intended remote TLS MONGO_URL and DB_NAME
  when you explicitly execute. Create/configure it per Section 18 if needed.

17.D EXPLICIT OWNER EXPORT / EMPTY-TARGET RESTORE ONLY

  ONLY after authorizing the destination and actually pausing writes:

    & $Py scripts\mongo_transfer.py export --env-file "$SourceEnv" --archive .private\authoritative.archive.gz --apply --confirm-writes-paused

  Export reads source and writes an exclusive private archive/log. Preserve
  them; do not overwrite/reuse an old archive filename blindly.

  ONLY for the selected remote TLS destination, verified genuinely empty:

    & $Py scripts\mongo_transfer.py restore --env-file "$TargetEnv" --archive .private\authoritative.archive.gz --apply --confirm-empty-target

  The helper checks actual target records and refuses nonempty destinations.
  It does not add --drop, merge/delete or overwrite an existing database.
  Keep DB_NAME unchanged. --source-db-name is only for an expressly reviewed
  namespace rename, not a guessed repair for missing collections.

  A failure can leave a partial archive or partly restored NEW target. Keep
  the private logs/target for review. Do not delete a nonempty database or
  bypass the refusal to make the next attempt appear successful.

17.E PRIVATE MEDIA PLAN / COPY

  Default LOCAL-FILES plan: no remote requests, writes a new local manifest:

    & $Py scripts\import_private_media.py --source-media "$SourceMedia" --audio-cache "$SourceAudio" --manifest .private\media-plan.json

  It preserves namespace/object bytes. Conflicting cache/durable bytes,
  symlinks and unsafe paths stop instead of choosing a replacement silently.

  ONLY after approving the actual authoritative local bytes and PRIVATE
  target store, the real upload/read-back-verification command is:

    & $Py scripts\import_private_media.py --source-media "$SourceMedia" --audio-cache "$SourceAudio" --manifest .private\media-applied.json --env-file "$TargetEnv" --apply --confirm-authoritative-source-and-private-target

  This consumes storage upload/download operations. Existing objects must be
  byte-identical; new writes forbid overwrite. Reviewed resumption can skip
  identical objects but needs a NEW manifest filename. Nothing is deleted.

  This is local-files -> private-Blob, not a universal remote vendor exporter.
  Old vendor-specific absolute URLs/keys need an explicit mapping/compatibility
  review. Do not regenerate original audio/photos/reels to hide missing bytes.

17.F VERIFY BEFORE CUTOVER

  With target writes still stopped:

    & $Py scripts\data_inventory.py snapshot --env-file "$TargetEnv" --output .private\target-after.json
    & $Py scripts\data_inventory.py compare .private\source-before.json .private\target-after.json

  database_equal=true means canonical records match under that tool/version.
  media_equal=null means remote media was NOT compared; it is not a media
  success. Use verified transfer manifests, retained source hashes and actual
  object coverage for that part. Review indexes and representative ORIGINAL
  balances, entitlements, history, media and settlement markers without new
  purchases, generation or credits.

  Preserve the original JWT_SECRET EXACTLY. Do not rotate it because a new
  host was created. If an old secret is too short for release guards, obtain
  an explicit encryption/key-migration plan; do not break saved keys to make
  a minimum-length check pass.

  Only after authoritative database, original media, missing-history
  reconciliation and backups are genuinely confirmed may the owner set:

    DATA_IMPORT_CONFIRMED=true

  For a genuinely approved fresh empty project, this means confirming that
  no prior data/media is expected, not pretending a transfer happened.

  Start only the intended new app/recovery worker. Do not let old and new
  worker generations manage the same unfinished jobs simultaneously. Retain
  original data/backups for rollback. See docs/DATA_PRESERVATION.md for the
  complete safety contract.

checkout is required to complete the read-only deployment checklist.

22.A HEALTH / BOOT

  1. In Render Events/Logs, confirm the expected successful build/start and
     one web instance. Release configuration/storage refusal is not a warning
     to ignore. Check for actual readiness, not an endlessly restarting app.

  2. Open in a full external browser tab:

       https://YOUR-ACTUAL-HOST/api/health
       https://YOUR-ACTUAL-HOST/api/ready

     Or read-only PowerShell:

       Invoke-RestMethod "https://YOUR-ACTUAL-HOST/api/health"
       Invoke-RestMethod "https://YOUR-ACTUAL-HOST/api/ready"

     health reports process/version; ready pings Mongo. Neither performs
     paid writer/TTS/Stripe probes. They are intentionally exempt from the
     extra beta form for Render's readiness checks. They do not prove Blob
     ownership, OAuth acceptance, AI credit or end-to-end payment fulfillment.

  3. Open the base HTTPS origin. Enter the additional beta password, then
     inspect the intro, sound gesture fallback and explicit 21+ consent.
     The beta password must not replace normal account login/data isolation.

22.B ORIGINAL DATA / ACCESS

  4. Sign in only with an owner-approved account. Reauthentication after an
     origin change is normal. Confirm original credits, entitlements, history
     and existing purchases against the authoritative source/receipts.
  5. Open EXISTING show transcripts, photos, saved audio, share/reel records.
     Do not regenerate missing content or create another purchase as a check.
  6. Verify another authorized beta account cannot access the first account's
     private records/media. Do not make private storage public to fix a 404.
  7. Inspect an existing completed reel and download it in a full browser.
     Creating a NEW reel or first uncached audio sample can use quota/providers;
     decide and budget that separately. Mobile emulation is not phone proof.
  8. Confirm source download, development login and public Swagger/OpenAPI are
     not exposed in beta. Ordinary account 401/403 responses are not a reason
     to disable access checks or revive an Arena iframe session tunnel.

22.C PROVIDER VERIFICATION IS SEPARATE

  9. Settings capability flags mean CONFIGURED, not necessarily VERIFIED.
     Review each service deliberately: actual Google origin login, real mail
     sender/inbox delivery, requested/actual writer and voice reporting,
     private storage permissions, and Stripe TEST endpoint deliveries.
 10. Keep ENABLE_PAID_DIAGNOSTICS=false. Do not run historical real-QA scripts,
     repeat a consumed generation/checkout, manually top up accounts or select
     a paid model/voice test just because a diagnostic button exists.
 11. Only after explicit new owner approval and provider budgets should an
     end-to-end generation or genuine TEST purchase be made. Inspect existing
     request/session/ledger state before retries to avoid duplicate work.

23. UPDATING, BACKING UP, ROLLBACK AND FREE-TIER OPERATIONS
==========================================================================

NORMAL SOURCE UPDATE:

  1. Back up private configuration, authoritative DB and original media first.
  2. Review the change against your current app/customizations. Never replace
     rich native source blindly with a recovered older snapshot.
  3. Account for active generation/reel/payment work and choose a controlled
     application-write pause where needed. Do not stop/delete MongoDB.
  4. Commit/push only reviewed source. Inspect staged names for private data.
  5. Verify Render is connected to the intended branch and autodeploy remains
     manual/off. Choose Deploy latest commit only when YOU intend it.
  6. Runtime secret edits need an appropriate redeploy/restart; public frontend
     env changes need a rebuild. Do not run pip/Yarn in a Free dashboard shell:
     normal shell/SSH is not available and ephemeral edits are not deployment.
  7. Keep one instance/worker and the tested ultrafast encoder/thread settings.
  8. Verify health/readiness, gate and original data after the deployment.

BACKUPS:

  - Retain independent encrypted backups of Mongo records, private original
    media/object inventories, JWT and important provider/gate configuration.
  - Source Git history and Render image history are NOT customer backups.
  - Remote Blob objects are not a backup of Mongo references/credits, and a
    Mongo dump is not a backup of original Blob media.
  - Free provider tiers do not automatically supply a full backup/restore
    service. Review retention and perform an approved restore rehearsal on
    a separate empty target before trusting the plan.
  - Never commit private manifests, customer photos/transcripts, database
    exports, env files or API credentials while documenting a backup.

ROLLBACK:

  - If a new deployment fails, preserve logs/data and stop/revert only the
    new APPLICATION under your control. Retain old source and stores.
  - Do not restore an old dump over a database that has accepted new writes.
    Reconcile differences and ownership/settlement records deliberately.
  - Render's deploy rollback is a CODE/IMAGE action, not a database rollback.
  - Do not let old/new recovery workers manage the same unfinished jobs at
    the same time. The supplied request-level recovery is not a distributed
    durable queue/multi-worker architecture.

FREE-TIER SLEEP / INTERRUPTIONS:

  - A first request after idle can display Render's wake-up page. Let that
    deliberate request finish; do not repeatedly launch generation/checkouts.
  - Sleeping/restarted processes cannot guarantee background work or webhook
    delivery timing. Recovery/reconciliation runs while the process is awake.
  - If a response is lost, check original recent-show/reel/payment state before
    resubmitting. Provider usage can be billed even when the client disconnects.
  - Large reels/private downloads can exhaust small quotas quickly. Watch
    actual workspace/provider usage, not just whether the UI loads.
  - Do not use artificial keepalive traffic to defeat Free sleep, erase old
    customer objects to hide quota problems, or automatically upgrade plans.
    Pause the beta when a Free-only constraint cannot be satisfied safely.

BEFORE PUBLIC PRODUCTION / LIVE SALES / APP STORES:

  The Free beta is not certification of production or store readiness. Still
  review durable jobs, webhooks/outage recovery, backups/restore, monitoring,
  alerts, abuse reporting, privacy/retention/deletion, actual-origin auth/mail,
  provider/commercial-content eligibility, billing/tax/processor obligations,
  mobile/native platform rules, licenses/source distribution and physical
  device tests. A 21+ checkbox does not grant payment/store policy approval.

  Keep the required Clean/off-limits/consent/entitlement controls. No provider
  can be promised to generate universally uncensored output, and no template
  can guarantee store approval or that every advanced feature works on a
  sleeping Free host under simultaneous load.

24. RENDER TROUBLESHOOTING / EXACT ERROR MEANINGS
==========================================================================

"Dockerfile / render.yaml not found"
  Check the GitHub root and selected branch. Extract the ZIP before upload.
  Root Directory should be empty for the supplied flat layout. A ZIP-only
  repo or an accidental extra parent folder is not the required structure.

"Wrong runtime / trying to launch only Node or only a static site"
  Choose a Web Service with Docker. Leave Dockerfile build/start defaults.
  The supplied image builds React and starts FastAPI serving the same site.

"Build cannot resolve npm/PyPI package or image"
  Check actual build log, frozen lockfile, network/registry availability and
  supported pinned files. Reattempt a reviewed build if transient. Do not
  replace every dependency with latest, discard the lockfile, install Windows
  packages into Linux, or expose keys as build args to suppress an error.

"No listening port / deploy times out"
  Use the provided CMD with 0.0.0.0 and Render's PORT. Do not bind only
  127.0.0.1, force local port 3000/8001, run start.bat on Render, or launch
  MongoDB as the web service. Fix startup guard failures first.

"HTTPS_APP_BASE_URL_REQUIRED / EXPLICIT_ALLOWED_HOSTS_REQUIRED"
  Set the actual HTTPS origin and exact hostname. APP_BASE_URL includes
  https://; ALLOWED_HOSTS does not. Do not insert a wildcard or development
  mode to bypass this.

"PERSISTENT_JWT_SECRET_MIN_32_REQUIRED_DO_NOT_ROTATE_EXISTING_KEY"
  Preserve the correct existing secret. If a short historical key truly
  requires migration, stop for an explicit reviewed encryption migration;
  do not generate a different key and orphan saved BYOK data.

"DATA_IMPORT_AND_HISTORY_RECONCILIATION_REQUIRED"
  DATA_IMPORT_CONFIRMED is not true. Complete the authoritative data/media
  decision/verification. This is a deliberate guard, not permission to
  pretend data was migrated or reset a target database.

"RELEASE_REQUIRES_REMOTE_TLS_MONGODB / Mongo timeout / ready is 503"
  Use the actual approved remote TLS URI, exact DB user/password and DB_NAME.
  Check password URI encoding, Atlas IP access list for Render's ACTUAL
  outbound ranges, DNS/SRV, cluster availability and TLS trust. Never set
  tlsInsecure/invalid-cert flags or use localhost/SQL as a release workaround.

"PRIVATE_BLOB_TOKEN_REQUIRED / durable media unavailable"
  Confirm correct STATIC token, correct PRIVATE store, eligibility, access
  mode and quota. A Vercel management/OIDC token or public store is not the
  configured outside-Vercel adapter. Startup canary failure is not fixed by
  turning off storage checks or storing customer bytes only in /app/cache.

"BETA_REQUIRES_ADDITIONAL_PASSWORD_GATE / verifier invalid"
  Use the actual supported scrypt verifier and separate signing key. Do not
  paste the plaintext password or include surrounding dotenv quotes in an
  individual dashboard value box. Preserve all dollar signs exactly. Use
  the owner helper only if creating a genuinely new gate, not to overwrite
  an existing one casually.

"CORS_REQUIRES_EXPLICIT_HTTPS_ORIGINS"
  You probably copied local HTTP origins into cloud settings. Use same-origin
  deployment with CORS_ORIGINS empty/unset, or exact trusted HTTPS origins.
  Never use credentialed *.

"Explore button missing or source/old login tunnel visible"
  Check both backend and PUBLIC build settings. Add manual-service defaults
  from Section 19; set REACT_APP_ENABLE_PREVIEW_LOGIN=true, source download
  false and session tunnel false for Render, then REBUILD. Runtime-only edits
  cannot change already-compiled JavaScript.

"Old Arena URL / browser calls localhost / blank page"
  Keep REACT_APP_BACKEND_URL empty and ensure Docker rebuilt the current
  frontend. Confirm the actual deployed branch/commit and /app/frontend/build.
  Do not give external users the API port or put server secrets into JS.

"Invalid host header / HTTP 400"
  Review ALLOWED_HOSTS against the real assigned/custom hostname. Use only
  the intended canonical URL. Do not delete host validation or use *.

"401 / 403 on private API or media"
  Usually missing/expired account auth, ownership or entitlement, separate
  from the beta gate. Reauthenticate at the correct origin; verify original
  account linking. Do not make media public or bypass ownership checks.

"404 on old media while new pages load"
  A new empty store is not a migration. Check retained original namespaces,
  exact DB references and actual original bytes, including legacy cache.
  Approve a real mapping/export for older vendor URLs; do not regenerate or
  substitute files to hide lost history.

"Email enabled but registration/reset unavailable / no messages arrive"
  Verify EMAIL_TRANSPORT=resend, real RESEND_API_KEY, verified EMAIL_FROM,
  correct APP_BASE_URL and provider sender/recipient restrictions. SMTP ports
  are blocked on Free. No key/present flag guarantees deliverability.

"Google works in old preview but not new domain"
  Managed provider new-origin/callback acceptance remains a real dependency.
  Confirm /auth-complete.html/state flow and the chosen exact HTTPS origin.
  This version has no independent Google-client env switch. Do not remove
  state checks, create duplicate account credits or claim Supabase fixed it.

"Stripe webhook signature/TEST validation fails"
  Use THIS TEST SNAPSHOT endpoint's signing secret, not the CLI/old/live one.
  Confirm /api/payments/webhook, raw signed POST delivery and the four handled
  Checkout event types. Thin events are not the current parser's recipe.
  Recheck tracked Checkout owner/amount/currency/TEST status. Never manually
  grant credits from a redirect or create another purchase just to retry.

"Build disabled, service suspended or quota exhausted"
  Review actual Free hours, bandwidth/build minutes, provider quotas and
  service-initiated traffic. Do not accept a paid tier/trial automatically,
  spoof usage with keepalives or discard customer data. Keep beta closed
  while the real Free-only limitation is resolved.

"Out of memory / interrupted reel / repeated restarts"
  Free compute has limited resources. Keep one worker/instance, native thread
  limits and ultrafast encoder. Local synthetic checks are not proof of your
  actual Render concurrency/cgroup capacity. Do not add workers, duplicate
  jobs or resubmit billed generation blindly. Inspect existing status and
  logs, pause heavy operations, and reassess the hosting constraint honestly.

"I cannot SSH or open a shell on Free"
  Expected Free limitation. Use reviewed source/env changes and manual
  redeployment; perform owner-approved inventory/transfer tools from your
  own machine. Do not depend on ephemeral shell edits as a deployment plan.
