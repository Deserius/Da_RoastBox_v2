DA ROASTBOX INSTALLER v1.2.3 - ONE-CLICK LAUNCH + PRESERVED STORAGE FIX
==================================================================

Normal Windows use:
1. Extract ALL files from Da_RoastBox_Windows_Preinstalled.zip.
2. Open the extracted folder and double-click thelaunch.bat.
   The equivalent legacy start.bat still works. No separate install step.

Installer 1.2.3 RETAINS the richer 1.2.1 disk-space safeguards. It adds direct,
prepared Windows runtimes with offline first-run unpacking, verified online
Python setup when missing, without requiring winget, and automatic
handoff to dependency setup, server readiness and the default browser.
Do not use an obsolete hotfix filename from an older set of instructions.

IF SETUP SAYS [Errno 28] / [WinError 112]
This is a disk/quota problem, not proof of a bad API key or a broken database.
Check the project drive AND Windows system drive. Installing on E: does not
make a completely full C: healthy. Aim for at least 4 GiB free on the project
drive for a full online install/repair, plus Windows/browser/system working space.
The prepared bundle normally needs no pip/frontend install; allow at least 2 GiB
free after extraction for unpacking and initial runtime/database work.

The installer:
- Redirects Python/pip/ensurepip TEMP, TMP and TMPDIR into the project.
- Redirects the Python bootstrap installer's TEMP/TMP into the project too.
- Uses project-local Yarn/npm caches; pip download caching is disabled.
- Checks disk headroom for the actual stage and reports the relevant path.
- Removes verified Node/Yarn/Mongo vendor archives after extraction.
- Retains the verified Python installer in .cache/downloads for safe retry.
- Never automatically purges global/user caches, database or generated media.

After resolving the reported space issue, double-click the launch file again.
Partial installations are checked and resumed as needed. Do not use --repair
merely to retry after disk-full; it deliberately reinstalls more packages.
No installer can manufacture space, bypass quotas or fix unsupported hardware.

PRESERVE YOUR EXISTING INSTALLATION
Back up before source changes. Do not delete or replace backend\.env,
frontend\.env, .data\mongo, audio/media folders or configured persistent stores.
Do not blindly overlay recovered source onto a richer/custom native release.
A fresh source download intentionally contains no private keys or old shows.
Never stop/delete MongoDB to fix a pip/frontend dependency error.

If packages really are damaged: stop only the web-app window, leave MongoDB
running, then run start.bat --repair from the app folder. Normal startup needs
no commands. Read START_HERE.txt and docs\LOCAL_INSTALL.md for details.
